# Financials in Visuals — Skill 持续进化与跨发行人发布合同（v8.4-RC）

> **目标不是让所有行业共用同一图表模板**，而是让研究原则、证据语义、编辑标准、问题修复和交接机制在第 N 家发行人上仍然可靠。本文件约束流程；完整会计/视觉研究依据仍在唯一 `SKILL.md` 和 01–05 手册中。

## 一、五层互不代替的工作成果

1. **原始来源**：取得完整 PDF 字节、来源公告、更正/重述版本、物理页、SHA、单位、期间、合并/母公司、行列语义。官网与镜像字节等价必须另证；HTML 挑战页不是 PDF。
2. **财务事实**：typed 原值 + Decimal 元，三大报表及材料附注。区分事实、管理层说法、分析师推导、假设及缺失；不同业务层级/口径不可加，H1 流量与年末存量不可混为同比。
3. **研究判断**：公司经营机制、量化贡献与替代解释、最可能改变论点的重大风险、下一期可证伪指标。没有外部历史、行业、价格或同行来源时不做相应确定性结论。
4. **原创财务视觉出版**：每张图以单一研究问题选择语法，盈利分部在披露收入+成本并满足守恒时做逐分部金额加权桑基；负利润/有符号变化用瀑布。净利润→CFO、BS 两时点、现金变动各自采用独立会计约束。SVG 原始路径几何、实截图、文字与来源同等重要。
5. **真实发布与续航**：独立离线 HTML + 同一首页目录，源码干净重建、GitHub main 的实际 SHA/Actions、Cloudflare 真实路由/静态指纹；新对话无需依赖先前聊天记忆。

**上述任何一层 PASS 都不能代替另一层。** 人类第二研究员签核仍单列，不得模拟“独立审阅”。

## 二、每发现一个问题的强制闭环（P0/P1）

1. **REPRODUCE**：指出原始 PDF 物理页/行/列、原数据与实际网页错误；保存与这个错误直接相关的可执行最小失败样本。画面截图不是单纯视觉反馈，而是结果证据。
2. **ROOT CAUSE**：说明属于财务语义、原始证据、行业适配、图形编码、浏览器、部署还是交接；明确修复的是共同内核还是公司专用逻辑。
3. **FIX SOURCE**：从原报告修正源 ledger / parser / figure brief / renderer；重新生成 HTML。禁止只改最终 HTML 文案或仅在状态文件记待办。
4. **POISON REGRESSION**：针对同型错误添加一个会失败的反例测试，并保留原始正常样本。除了源金额，还覆盖经济含义、行列、图形几何、手机与真实生产版本。通用测试适用于多个发行人；单公司测试**不得冒充跨行业认证**。
5. **UPDATE SKILL**：若为可迁移根因，修订唯一 `skills/ashare-financial-storytelling/SKILL.md` 和必要手册/发布清单，而非留下互相竞争的 v7/v8 技能说明。同步写入 `quality-regressions.json`：失败根因、修复、代码证明、覆盖级别和仍未解决的事项。
6. **RUN REAL GATES**：实际运行 `scripts/check_release_contract.py`、`scripts/check_handoff.py`、适用会计与行业测试、完整浏览器 1440/768/390、GitHub Actions、生产 URL。必须记录确切提交、运行号、结果；旧站点的绿色不能换算为当前提交绿色。
7. **COMMIT HANDOFF**：最新 `PROJECT_STATE.md` 顶部及 `project-status.json` 同步；提供下一次可复制的执行路径。若无法跨越外部来源/真人/Cloudflare 权限，保持具体 `FAIL/NOT_CHECKED`，并优先推进仍可完成的工作。

**P0 应阻止未加警示的高质量发布**：错误的发行人/期间/币种/合并层级、缺原始完整 PDF、财务恒等式无法解释、虚构业务/数据、负毛利假桑基、重要图形面积错误、影响核心结论的源单元格错列、报告无法阅读。可单独保留**明确标示边界的来源限制预览**，但不能升为 verified_research。

## 三、第 N 家新公司的自动执行合同

- 唯一目录仍为 `site/research_catalog.json` → `public/index.html`。新增公司必须拥有真实 `public/<route>.html`、原始 PDF 归档、研究账本/计算程序、图形简报、测试、`research/issuers/<code>/release-gates.json`。
- 程序 `python scripts/check_release_contract.py` 在 GitHub Actions 验证**每个新代码**是否存在独立发布记录；核对 PDF 魔数、实际字节数与 SHA，路由、门槛枚举、PASS 的证明路径、来源约束、可复现证据以及研究类别。**绝不能停在 release JSON：还须检验其 source-ledger.json 的发行人、期间、原 PDF SHA、披露元/比例字段类型与源页标签，并检验 figure-briefs.json 的报告版本、源哈希、所引真实 fact IDs 和多种有效研究问题。** 机器校验元数据一致性不等于源 PDF 具体行列已通过独立语义审阅。
- `source_limited_preview` 至少要求 PDF、选定重大来源行列、核心会计、研究反论点、图形语义、实际视觉自检、浏览器与离线重建通过；可保留如实披露且不掩盖的附注例外、独立人员未审查和外部估值未覆盖。
- `verified_research` 在这些门槛之外还需要重大附注、外部历史/同行、线上发布和**真实第二人**完整 PASS；仅由单个助手自动运作时不会自然满足。门槛不是分数，不允许平均折抵。
- 银行、保险、地产、软件、光通信、芯片和制造等行业必须使用自己的**经济机制与报表定义**。不适用桑基须写源证据原因。行业声称已泛化需有至少两份不同行业/发行人原始报告完整验证及对抗测试，不以一张图覆盖测试代替。
- `legacy_pre_contract` 是固定七家旧公司：它们**没有**因为引入新合同就自动获得认证；继续按逐家公司补齐来源、重大附注、视觉审阅与线上检查。新增公司不得被插入豁免名单。

## 四、真实覆盖能力分级

| 级别 | 可声称的范围 | 不可声称 |
|---|---|---|
| L0 | 规范/研究提案 | 已处理真实财报 |
| L1 | 一家真实 PDF、特定财务关系、真实浏览器和源证据 | 已支持该行业所有财务附注及研究 |
| L2 | 同行业至少两家独立真实 PDF 的全面三表/材料附注/行业机制/独立 HTML + 反例和实截图 | 其他行业自动适用 |
| L3 | 至少两个不同会计行业路线的 L2，以及跨公司回归、真实多期与公开部署测试、独立审稿 | 未经审查的所有 A 股公司 |

准确说法是：**v8.4 质量合同已实现第 N 家的机器验收入口；行业实际覆盖仍须单独逐家公司证明。**

## 五、交接的最小事务记录

结束前必须在仓库内留下：`main` HEAD、工作 PR/branch、对应 Actions 与产物 SHA，新增/变更的发行人代码与 HTML 路由，PDF 来源/归档路径/版本/物理页/哈希，每项 `PASS / FAIL / NOT_CHECKED`、源异常及结论影响、实际 SVG/文章 1440/768/390 图像证据、Cloudflare 本次静态版本是否一致、下一步精确执行命令。

一个错误若无法本轮修复，也要写出**需要哪张原报告附注/哪个源表/哪个提供方**，不可仅写“后续优化”。成功的本地 CI 不自动关闭线上的失败。

**回归登记簿：** `skills/ashare-financial-storytelling/quality-regressions.json`。**第 N 家质量登记：** `research/issuers/<code>/release-gates.json`。**自动校验：** `scripts/check_release_contract.py` 和 `scripts/test_check_release_contract.py`。**旧七家公司欠账：** `PROJECT_STATE.md` 和 `project-status.json`。

> 重要边界：本次工具可以核对 JSON、文件存在性、真正 PDF 字节和检索到的历史 GitHub 运行证据；不能从 JSON 自行证明视觉美感、附注全部正确、Cloudflare 当前版本或第二位真人审核。它们仍需实际执行相应审核。
