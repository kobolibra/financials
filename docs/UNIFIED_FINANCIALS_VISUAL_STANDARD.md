## 直接研究过的 App Economy Insights 公开一手参照

1. [How to Analyze an Income Statement](https://www.appeconomyinsights.com/p/how-to-analyze-an-income-statement) 中 Apple FY22 的真实产品/服务收入 → 总收入 → 成本/毛利 → 费用/经营利润 → 税收/净利润逻辑；**灰 = 收入，红 = 支出，绿 = 利润**。业务节点的名称、金额、收入变动、毛利率直接放在图中，而不是仅用长说明注解。
2. [How to Analyze a 10-K](https://www.appeconomyinsights.com/p/how-to-analyze-a-10-k) 的 Apple FY23 公共财务示例，逐级汇总有业务含义的产品与服务；分析顺序是经营结构→风险→三表→MD&A→附注，而不是照财务报表按页转译。
3. 财务图形自身不是经济分析：即使像 AEI 示例一样完成资金流，仍须结合与前期/同行对比和经营机制。**不能把 Apple 产品收入图照搬到中国保险、银行或有真实负分部毛利的报表**。它提供的是信息架构对照，不是授权复制视觉作品/品牌。

## 统一的 7 项强制版式准则

1. **一个主要问题与可证伪的一句话答案**。首屏最显眼的是经济机制，不是 EXHIBIT 编号、会计系统内部变量或无意义大数字。
2. **一张真实原始金额图有三层阅读**：来源→**一个**总收入实体→合法成本和利润终点；若有会计证据，则继续延伸毛利→费用→经营利润；若引入投资收益/负值，必须**换成有符号利润桥**，不能虚构正向流。
3. **所有连接线真实连接节点**；禁止四组不连贯的矩形带叫“桑基”；禁止集团内部业务子项叠加母项、地理+产品重复叠加。
4. **四种恒定语义配色**：收入源灰蓝 `#9CABB2`，汇总节点深蓝灰 `#263F47`，费用低饱和红 `#CD7271`，利润深绿 `#239878`；负值按真实符号明确，背景低色温 `#F8F7F2`，中文文字 `#19333C`。颜色服务定义，不服务装饰。
5. **一个共同金额尺度**：精确 Decimal CNY 元；曲线端点厚度＝原始金额÷比例，所有中间节点及最终节点精确守恒。不设“0 元最少 2 px”。极小值使用精确金额直标＋**明确独立尺度**的局部小图。
6. **桌面与手机两套原生构图，同一财务语法**：桌面 1100 SVG 单位，手机 330；390/768/1440 使用真实 CJK 浏览器核验全图可见、标签边界、不重叠、导出实际当前版本；没有 850px 横滑“小桌面”或隐藏图。
7. **每张图同时拥有故事与证据**：标题/核心结论/一条有价值反证、年份与合并范围、关键利润率或同比、可交互原 PDF 页及数据行、SVG 全元金额元数据。内部机器标志仅 DOM 属性，不能露在中文正文。

## 合法图形语法与强制替代图

| 会计情况 | 图形 | 强制禁止 |
|---|---|---|
| TYPE A：业务收入及各自披露成本 | 真连接的来源→收入合计→各自成本/毛利→合计成本/毛利 | 用集团平均利润率代替逐业务真实 GP |
| TYPE B：只披露独立业务收入及集团 COGS | 来源→总收入→集团 COGS/GP；中文提示“无法倒推分部毛利” | 把末端合计 GP 错视为某业务自己的利润 |
| BANK：已净额的净利息、净手续费、其他净收入 | 净收入来源→总净收入→管理/信用/经营费用、营业利润 | 把利息支出从已经净额的 NII 中扣第二次，或叫工业“毛利” |
| TYPE C：负业务毛利、交叉分类、非正资金 flow | 真比例有符号图＋明确局部尺度；跨年比用统一轴，现金用带符号会计桥 | 将负数画成正资金桑基，或加入虚构“差额”“其他” |
| 保险管理层旧保费统计（601628） | **保费来源四项→新单／续期两组→总保费**，使用全站同一灰蓝／深绿／金棕设计、金额守恒、真贝塞尔；另以独立 CAS25 服务收入组成与签名利润桥表达法定会计 | 绝不把统计保费连接到 CAS25 服务收入、经营收现、CSM 存量或归母利润 |
| 资产负债表、保险 CAS、银行监管比率 | 同期存量结构、期限/偿付约束、保险服务收入/CSM 各自独立图 | 把时点存量画成资金流；把保费、保险收入、CFO 视为同类收入 |

**核心通用渲染器**：`research/shared/unified_income_sankey.py` 的 `FlowPlan.check()` 与 `render_income_sankey(plan,mobile)`，通过 `research/rebuild-v10/unified_finance.py` 将真实行业 ledger 类型适配到同一结构。图形源码均不得在公司生成器中重新实现另一种“类 Sankey”。目前除 V10 A/B/BANK 公司外，真正独立原始报告生成器也已经接入主图：三家光通信通过 `research/shared/v7_optical_income_adapter.py`，翱捷科技、长江电力、恒瑞医药通过 `research/shared/source_income_adapter.py`；中国人寿因不允许将保费与 CAS25 服务收入混合，使用 `research/shared/unified_insurance_premium.py` 的独立 **四来源→新单／续期→总保费** 真连接桑基，共用视觉 token 但绝不是工业 COGS 流。茅台 C 的有符号图沿用不同合法语法。**这七家只是主桑基完成统一，整份报告其他旧财务图尚未统一。**

## Skill 与持续产出：把文档承诺变成三个不可互相替代的门

- `FINANCIAL_SOURCE`: 原 PDF 字节、实际页和源账本、Decimal 金额与各环守恒、重大例外和反证。
- `RESEARCH_DEPTH`: 各公司核心命题、量化经营驱动、最强替代解释、缺失的多期/同行/价格数据，明确禁止虚构。
- `VISUAL_EDITORIAL`: 一张图是否真正表达经济机制、统一图形语法与 token、五秒内读得出什么、3 端真实布局和读者导出，独立专业视觉审查。

`scripts/check_handoff.py`、`scripts/check_pr35_quality_handoff.py`、`test_editorial_chart_quality.py` 与真 PDF 重建/浏览器/Cloudflare 需要对同一原始 HTML SHA 通过。**即使全部自动 PASS，没有独立财经分析师与视觉总编的真实审核仍为 NOT_CHECKED。** L1 新报告期/新公司不重写 renderer 成功后才能声称稳定；L2 必须有 20–30 未见原始 PDF 多期/多行业样本和真实独立人工盲评。只用 4 家旧报告反复成功不能证明长期高质量。
