## 1. 参考的究竟是什么

- [AEI: How to Analyze an Income Statement](https://www.appeconomyinsights.com/p/how-to-analyze-an-income-statement)：以 Apple 产品/服务收入→成本→毛利→利润梳理真实营业经济，区分成本与盈利，并明确银行/保险不同。
- [AEI: How to Analyze a Balance Sheet](https://www.appeconomyinsights.com/p/how-to-analyze-a-balance-sheet)：同日资产＝负债＋权益，不能把存量与期间现金运动混淆。
- [AEI: How to Analyze a Cash Flow Statement](https://www.appeconomyinsights.com/p/how-to-analyze-a-cash-flow-statement)：从净利润和完整非现金调整到CFO，再到投资、融资、汇兑与现金首尾。
- [AEI: 6 Charts Before You Buy](https://www.appeconomyinsights.com/p/6-charts-before-you-buy)：8–12季度增长/利润率、资产负债与杠杆、股价与基本面、历史估值、同行；没有实际独立数据就不能制造趋势。
- [AEI: Alphabet Q3 FY24](https://www.appeconomyinsights.com/p/google-little-engine-that-cloud)：把业务分部、利润率、现金和资产结构服务于同一个主线，全文付费部分不能假称已读。
- [Financial Times Visual Vocabulary](https://github.com/Financial-Times/chart-doctor/tree/main/visual-vocabulary)：图形由流量/组成/对比/偏差/时间等关系选择，而非统一 Dashboard。

**可超出的维度**必须真实执行：人民币原始元逐表格 x/y 及物理页溯源、CAS语义和重大附注反证、净利润与CFO完整有符号勾稽、真正金额几何、全离线可重建 HTML、可见反方观点。漂亮且没有这些实证的图，不能叫超越。

## 3. 三层桑基决策树——这才是核心，而非「有桑基就算通过」

**A：来源业务逐项有成本/毛利（最有解释力）**：对相同期间、币种、合并范围、互斥同层级商品或合同来源 i，原始元逐项验证 收入_i=披露成本_i＋推算毛利_i，三项必须可非负绘流。必须用来源_i→自己的成本_i＋毛利_i→两个合计终点，合计精确守恒；有合法后续经营层才加后续流。不能退化成仅源→总收入→集团成本/毛利并声称解释「哪个分部创造毛利」。

**B：仅各来源收入＋集团层成本**：可以形成严格守恒的两阶段集合流，但必须命名 GROUP_ONLY_GROSS_ALLOCATION，明确**不识别分部自身成本及利润**，不能冒称分部盈利归因；若PDF披露更细逐业务成本必须改用A。这个局限应在图题与一眼可见的反方注释中，而不只是藏在附录。

**C：不合法**：只有一个业务源、分组交叉/层级重叠、净负毛利、合并抵销为负、保险保费和法定服务收入不属同一组、港口TEU与收入是不同单位、债券市值与现金为不同期间或存量/流量。写出 FINANCIAL_SANKEY_OMITTED_WITH_SOURCE_REASON；用有符号瀑布、嵌套子集、二期对照、利润率与金额组合或排名图。绝不能发明「未披露其他」节点。

**所有真正资金图**：source节点、目标节点及每条正向 ribbon 的SVG真实矩形/曲线宽度必须精确按原元金额同一尺度；0为0，不许min-width=1px的经济假象。极小源另给图外文字及原始数据表。不仅验证HTML data-value，更要解析SVG path真实几何、期初期末、每个分部利润口径。守恒通过但不能回答研究问题，视觉编辑仍是 FAIL。

## 4. 其他会计关系必须另用独立语法

- 利润表：从同口径毛利到营业利润、税前、合并和归母净利，用真实正负方向，不许从税前金融公允价值扣税后非经常利润而未做完整桥。
- 净利到CFO：有真实间接附注才使用全部原调整；仅有直接法则逐实际现金收支，不可用BS余额变化代替原表调节。
- 现金：期初现金等价物＋CFO＋CFI＋CFF＋现金汇兑＝期末；不能用总货币资金冒充。
- 资产负债：同日资产＝负债＋全部权益，两日同一宽度基准对比，禁止作为现金流向描绘。
- 资本：现金已付CapEx/非现金背书票据/未来承诺/在建工程账面存量分别显示。
- 历史与估值：8–12独立季度、市场价格、真正同行和倍数缺少有日期的原始数据，必须 NOT_CHECKED，不能填空式图表。

## 5. 5秒视觉验收：人类编辑检查不是颜色喜好评分

对每一张主图，先填写带来源事实 ID 的 figure brief：研究问题、准确结论、报告页与本期对照、单位、合并/母公司、排他分组、原元算式、图形家族、零点及符号、手机重排、可见反证和源表。**以下任一失败即图形编辑FAIL**：

1. 5秒内无法从图题和直标看懂这家公司的关键驱动及重要性；或表格比图形更快更清楚。
2. Ribbon面积、节点高度或瀑布转折不是原金额比例，或数值虽正确但汉字BBox越界、零点和负数视觉错误。
3. 图文产生「盈利了所以收现」的错误会计因果，或不同单位/时期/分类层级被画成同一个总和。
4. 首屏是行业通用柱状表，而公司最重要的业务机制、最大成本和重大现金矛盾藏到后面。
5. 390px只能看到850px桑基的左侧，或者把非桑基图直接display:none后以数字列表取代全部可视化。
6. 一个名为桑基的group-only图被包装成单产品毛利贡献；1源2出口虽算数正确却缺少足以解释业务的额外信息。
7. 全篇用统一视觉卡片机械堆叠，没有层级轻重、阅读节奏、图间经济逻辑和邻图的反方解释。
8. PDF原始页、元金额及数据边界藏在无法到达的弹窗或不同离线文件里。

**视觉PASS凭据**：真Noto中文Chromium 1440/768/390：全文页和**每张金融图独立截图**；SVG source/path精度与可见文字BBox；点击正文、PDF锚点、导出SVG与返回目录；图像直接批评（标题、信息量、空间、重叠、误导）；真实Cloudflare公司与首页的全文SHA。同一SHA以外的验收全部失效。真实第二人类审稿不能伪造。

## 6. 本次审阅发现的现行生产代码硬缺陷

以2026-11-05当前 main 中四家公司研究页来源工程 research/rebuild-v10/publisher.py 为例：

- 手机 CSS 明确含有 .graphic-svg{display:none}，只让 .graphic-svg.sankey-svg{display:block}；换言之**在390px隐藏所有非桑基的主要SVG图**，数据表不是替代图形出版。
- 只剩的桑基又被指定 width=850px/min-width=850px 放入水平 overflow-x:auto，小窗看不见整图；与用户要求的真正390原创金融图完全冲突。
- .github/workflows/verify-v10-sankey-research.yml 的旧移动端验收居然 assert render['sw'] > render['cw']，把**图内需要横滑**作为成功条件，反而允许视觉退化绿色通过。
- V10中的来源→集团总成本/毛利在会计范围内可守恒，但在原文件存在同业务成本明细时，该图**不构成各业务毛利归因**，与AEI强烈的业务利润视觉主线仍有差距。
- 历史11×3 CJK审计 #41783946027 已提供原来源宽度、PNG证据；其中先前三家、688220、600276、600900、601628后来有各自源SHA真线上修复；现存明确 **四家** V10 390图形仍 FAIL。旧历史截图不是本次新main逐图真截图证书。
