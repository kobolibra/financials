# Playbook 06 · 泛化：没见过的公司、行业和新变化怎么处理

目标：拿到**任意一家** A 股公司的完整定期报告（一季报、半年报、三季报、年报），不写任何公司专用代码或规格，就能得到逐格可追溯的账本、闭合的会计恒等式、经过审计的图，以及方向已核对的分析要点。遇到工具处理不了的情况，必须**报出来**，不能静默吞掉。

## 1. 为什么能泛化：准则把格式定死了，公司差异只在边缘

财政部的报表格式（一般企业 / 商业银行 / 保险公司 / 证券公司）规定了三张表的行项名称和小计结构。各公司真正不同的地方，以及本 Skill 的处理办法：

| 差异 | 真实例子 | 通用规则（`tools/statement_extract.py`） |
|---|---|---|
| 标题前缀 | `1、合并资产负债表`、`截至…期间合并利润表`、`年半年度合并及公司利润表`、`未经审计合并现金流量表`、`2、合并年初到报告期末利润表` | `TITLE` 允许编号、日期或期间短语、"未经审计"前缀，拒绝句子（含 的/中/在/，） |
| 审计意见里提到报表名 | 万科审计报告逐行列出"合并及母公司资产负债表…" | 只有真正收集到数字行的标题才会结束一张报表 |
| 一页多表 / 续页 | 母公司报表从合并报表最后一页的中部开始 | 按**标题所在行**切换报表，不按整页切换 |
| 合并与公司同表 | 美的：合并及公司四列 | 取最左边两列有效金额列（合并列在前） |
| 附注列 | `营业收入七、48`、`四(46),十七(3)`、`(五)41`、单独一列的 `56` | 识别附注列的引用格式并去掉；附注号单独成行时，向相邻行借回项目名 |
| 项目名折行 | `投资收益（损失以“—”号填` / 数字行 / `列）` | 向上下相邻的空行借文字后再规范化 |
| 填列说明 | `（损失以“－”号填列）`、`(损失以“()”填列)`、`财务(费用)/收入` | 统一去掉；`(费用)`、`/收益` 这类符号提示也规范掉 |
| 单位 | 元 / 千元（宁德时代、美的、三一）/ 百万元（中国人寿、招行） | 在标题下方的表头行读取单位，并沿用到续页；每个单元格记录 `unit_scale` |
| 负数写法 | `-1,234.56`、`(1,234)` | 两种都识别 |
| 费用符号 | 一般企业：费用为正数；国际准则风格（美的、招行、中国人寿）：费用为负数 | 按大额成本行判断整份报告的口径；账本统一为"费用为正"，单元格标 `sign_flipped`，校验器读回时按翻转后的值核对 |
| 行业格式 | 银行（利息净收入、吸收存款）、证券（代理买卖证券款）、保险（保险服务收入） | 依次检测保险、证券、银行；**只要出现"营业成本"就按一般企业处理**（茅台、美的有财务公司） |
| 营业总收入/总成本里的金融项 | 茅台、美的、海尔有财务公司的利息收支 | 用明细项（`fin_interest_*`、`fee_*`）闭合恒等式；损益流向图里列为"金融及其他营业收支" |
| 四舍五入 | 千元报表的小计与明细差 1 千元 | 两个打印单位以内的差额记为"报表尾差（四舍五入）"：在恒等式里单独列出，在流向图里是一项可审计的净额，不并入任何科目 |
| 原件自身错误 | 万科 2026H1 印出的营业总成本 = 营业成本 | 以明细为证据；小计不符记入 `source_anomalies`，在文章里如实披露，不修补 |
| 封面没有年份 | 中信证券封面只有"半年度报告"；A+H 股第一页是港交所免责声明 | 先读前 3 页，找不到再读前 8 页的页眉 |

## 1b. 附注表也自动化（`tools/notes_extract.py`，由 `fin_intake.py auto` 一并运行）

原则：**表头不可信，用报告自己的数字证明每一列的含义**。不能证明的表格不使用，并在 `notes_tables` 里报出来。

| 附注 | 证明方法 |
|---|---|
| 营业收入和营业成本（主营业务 / 其他业务 / 合计） | 合计行的某一列等于报表营业收入，才算本期收入列；成本列、上期收入列、上期成本列同理，各自要等于报表上对应的数。只有 2 列、只有收入、"收入 成本 收入 成本"这几种排法都能识别 |
| 分产品 / 分行业 / 分地区 / 分销售模式（沪深两市的营业收入构成表、10% 以上表、附注分解表） | 同一张表里连续几行某一列加起来**恰好等于**营业收入或主营业务收入，才算一个完整维度。其余列只有合计也能对上时才被赋予含义。表头缺失的维度（深市 10% 表把产品和地区写在同一个表头下）按合计切分；地区名称自动判为地区维度 |
| 成本列无法用合计证明时 | 只接受与已证明的收入列一致的表头含义（`cost_proof: HEADER_CONSISTENT_WITH_PROVEN_REVENUE_COLUMNS`）；其他业务成本可由"营业成本 − 主营业务成本"得出（两个同期披露数相减，记为 DERIVED） |
| 业务毛利桑基 | 维度的收入和成本都闭合到报表营业收入和营业成本，并且没有负毛利行，才生成 `income_partition`；有负毛利行（茅台年报的"其他业务"）就换下一个维度 |
| 现金流量表补充资料 | 表中的净利润和经营现金净额必须等于合并报表（母公司表不会被误取），且各行加总恰好闭合；上期列也闭合才保留 |
| 扣非归母净利润（主要会计数据） | 先在同表找到等于报表的归母净利润行，确定本期和上期所在的列（三季报的年初至报告期末列、重述后的"调整后"列），再在扣非行取同样的列 |
| 单元格 | 每个附注事实都要能从 PDF 单元格读回；读不回的整张表丢弃（`dropped_unreadable_cells`），不修补 |

## 1c. 年报

年报的三张表格式与半年报相同，比较期为上年末（存量）和上一年度（流量），`stock_dates` 已处理。2025 年报 11 份（天孚、茅台、万科、宁德时代、中国人寿、中信证券、海尔、太辰光、牧原、三一、金山办公）首轮 9/11 通过。暴露的两个变体（`营业利润(亏损)`；项目名折成三行）用通用规则修复后 11/11。

## 2. 标准流程（任何公司都一样）

```
T=skills/ashare-financial-storytelling/tools
python $T/fin_intake.py init --code C --pdf report.pdf --url <巨潮链接>      # 识别期间、归档、存哈希
python $T/fin_intake.py auto --code C            # 三张表 → 标准账本；报告格式、恒等式、未映射行、原件异常
python $T/fin_intake.py auto --code C --write    # 恒等式闭合后才写入账本
python $T/fin_intake.py facts --code C --spec …  # 只用于附注：分部、地区、非经常性损益、现金流补充资料
python $T/v2_builder.py findings --code C        # 通用分析规则，按重要性排序，方向已核对
python $T/v2_builder.py flowspec --code C        # 损益流向图的阶段定义（逐元闭合）
python $T/v2_builder.py numbers|scaffold|apply …  # 见 SKILL.md §2
python scripts/generalization_probe.py <pdf>     # 只给 PDF 的端到端自检
```

`auto` 报出的每一项都有对应处理：
- `identities_failed`（残差）：某个行项漏了或符号错了。看同一张表的 `unmapped_rows`，在 `CANON` 里加同义词并补回归测试。
- `source_anomalies`：原件自己的问题。在研究稿的"重大附注"里写明。
- `unmapped_rows`：本 Skill 还不认识、但金额存在的行。只要恒等式闭合，就不影响已有图表；需要用到时再加入 `CANON`。

## 3. 图种按数据自动降级，不硬画

| 情况 | 结果 |
|---|---|
| 一般企业、盈利、正向损益不超过所承载的利润 | 损益流向图 V3（`income_flow_v3` + 独立审计） |
| 亏损（牧原、万科）、正向损益大于所承载的利润（翱捷） | V3 拒绝 → `v2_builder.income_bridge` 生成从营业收入到归母净利润的签名桥，逐元闭合 |
| 银行、证券、保险 | V3 拒绝 → 同样走签名桥；看板用营业利润率代替毛利率；营运资本图改用贷款、存款、金融投资、保险合同负债等科目 |
| 某个比率为负 | 利润率对比图只保留非负比率，负值交给桥图 |
| 某项没有上年同期数 | 对应注记省略，审计器也不期待该注记 |

## 4. 通用分析规则（`v2_builder.findings`）

与行业无关，每条都由数据决定方向和措辞，数字一律用宏：成本与收入增速差 → 毛利率变化；营业利润增速与收入增速（区分收入增长与下降两种情况）；经营现金 / 净利润；应收增速与收入增速；存货变化；费用率变化 ≥0.3 个百分点；财务费用正负翻转；减值增加；少数股东占比 ≥10%；非经常性损益使归母与扣非偏离 ≥5%；资产负债率变化 ≥1 个百分点；分部增速分化 ≥5 个百分点。行业专属问题（例如银行的净息差、保险的新业务价值）依赖附注，仍由研究者在 P3 补充。

`apply` 在两处挡住"写反方向"：
- 宏前面的方向词（增长、上升、下降、减少等）与实测符号不一致，就失败。
- 大写宏（`[P:gm]`、`[D:ar]`、`[G:rev]`）输出绝对值，前面必须带方向词，避免出现"上升+1.11"这种写法。

## 5. 证据与边界

- `research/quality/generalization-probe/result.json`：19 份原件，涵盖 18 家公司、4 种报表格式、3 种报告期，只给 PDF，全部通过。其中 5 份是盲测（中信证券、万科A、宁德时代、三一重工三季报、牧原股份），第一次运行暴露出 7 类问题，都以通用规则修复。
- `tools/test_statement_extract.py`：仓库内全部原件的恒等式闭合；抽取结果与人工账本逐值一致（> 600 个值）；单元格可从 PDF 读回；漏掉一个行项时会报残差。
- 30 份原件（含 11 份年报）的附注覆盖：业务毛利桑基 16 份（其余没有能闭合到营业收入和营业成本的完整维度）；现金流量表补充资料 27 份应有披露，闭合 22 份（宁德半年报差 173 千元、中信年报、两份保险报告未通过，全部报出、不使用）；扣非 26/30。
- 仍不在范围内：银行、证券、保险的附注（净息差、分业务手续费、新业务价值）；研究判断和人工审稿不能由工具代替。
- **新变化的处理方式**：只加通用规则加回归测试，不写公司补丁。改动 `CANON`、`TITLE`、`norm` 后，必须重跑 `generalization_probe.py` 覆盖全部原件。
