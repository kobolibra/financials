# Playbook 03 · 图形系统：AEI 式财报视觉语法 + 本库渲染器映射

AEI 的财报图之所以一眼可读，靠的不是配色本身，而是几条稳定的信息设计规则：金额决定宽度；灰色=收入、红色=成本费用、绿色=利润；每个节点直接标注名称、金额、同比与利润率；从左到右只讲一条利润链；次要细节合并为有名称的小项；图上方一句话说明这季的事。本系统采用这些规则的**原创实现**，不复制其图像、品牌或字体，并加上 A 股会计合法性约束。

## 0. 从 AEI 学到的规则（2026-11-16 研究 Apple FY22 损益图、"6 Charts" 与 Netflix 财报文）

1. **一篇文章有多种图，不是一张桑基加一串桥。** AEI 财报文的结构是：钩子 → At a glance 数字 → 损益流向图 → 3–4 个主题小节（每节 1–2 张趋势图：季度柱、利润率走势、分部增速）→ 结论。累计桥只在解释"为什么"时出现。
2. **损益流向图的语法**：左→右一棵树；收入分部 → 营业收入 → 毛利（绿，向上）/ 成本（红，向下）→ 营业利润 / 费用 → 净利润；费用与最终扣减拆成**具名红色叶子**，各标占收入比例；利润节点标金额、利润率（含 pp 变化）、同比；收入灰色，节点实心条、彩带浅色。
3. **每张图一句结论在图上方**，图下给趋势、重点、反证（AEI 的 Trend / Callout / Highlight，本库为"趋势 / 重点 / 反证"）。
4. **数字直接标在图上**（柱顶金额 + 同比），不靠坐标轴读数。
5. **少即是多**：小于收入 1% 的费用合并为一项具名"其他"，完整明细留在核对表。

本系统采用这些规则的原创实现，不复制 AEI 的图像、品牌或字体，并加上 A 股会计合法性与逐元审计。

### 选图算法（EDITORIAL_V2，先有证据再有图）

**前置门禁：** 先运行 `v2_builder.py capabilities --code <code> [--period P]`，检查 `visual_candidates` 的 `ELIGIBLE_PENDING_SOURCE_AND_VISUAL_AUDIT`、缺证据原因与行业路由。以下是**工业公司证据足够时的编辑候选顺序**，不是任何行业都硬画的四到六图套餐。数据不足就用明确的未证/省略状态，不得因配额制造假信息。其他行业要先实现可独立审计的新适配器，见 Playbook 07。

1. 第一张：`kpi_board`，6 格：营收、毛利率、归母、经营现金、本期最能说明问题的单季或分部数、最大风险存量（如存货/应收）。
2. 损益流向图（E2）紧随其后（`editorial.hero_position = "after_first"`）。
3. 增长主题：季报/半年报用 `period_columns`（营收与归母各一张）；年报用分部 `growth_bars` 或多年柱。
4. 利润率主题：`ratio_dumbbell`（毛利率、营业利润率、归母净利率、主要费用率）。
5. 现金与资本占用主题：`stock_delta` + 至多两张 `signed_bridge`（现金形成、利润→现金）。
6. 其余桥、两期表、资产负债：进核对层（`role: reference`）。
7. 当前工业报告的编辑 lint：不同图族 ≥ 5、正文签名桥不超过一半、至少一种可比较趋势图、3–4 个章节。**这是既有排版多样性检查，不是财务信息的合法性证明**；未来要根据能力编译器条件化配额。证据不足时必须放弃图种并标明限制，绝不倒推数据满足图数。`fin_intake.py preflight` 仍会执行 `lint_v2`，不得绕过失败直接发布。

## 2. 节点标注规范

- 收入来源节点：名称、金额、同比（TYPE A 另标毛利率）。
- 利润节点：名称、金额、利润率（含 pp 变化）、同比。
- 成本 / 费用叶子：名称、金额（括号）、占营收（含 pp 变化）。小于营收 0.1% 的叶子没有可见条形，标签改为灰色、小一号，但仍保留。
- 所有标注由独立审计器从本期与上年同期原件格重新计算（半数进位到 0.1），逐条比对 SVG 文字。缺上年同期源格时 V2/V3 渲染器拒绝。

## 3. 损益流向图 V3 的版式规则

- 桌面 1100 宽：收入分部列 x=160、营业收入 326、毛利 506、营业利润 686、叶子与归母 864（无分部时 150/370/590/860）。叶子标签需在 1100 内放下"（金额）　占营收 x%（±pp）"。
- 税前、净利、少数股东三层合并为"营业利润 → 归母净利润"一步，所得税、营业外支出、少数股东为红色叶子；其他收益、营业外收入等正向项为赭色流入。正向项超过承载利润或小计 ≤ 0 时拒绝，改用签名桥。
- 小于营收 1% 的费用合并为"其他费用及损失（N项）"，只剩一项时保留原名。
- 手机 330 宽：纵向流（利润在左、成本向右剥离），成本标签在条形下方右对齐，两行间距 ≥ 15；费用叶子单列为带比例条的列表（`data-chain-leaf`）。
- 使用 V3 时，主图下方不再重复"本期营业层主要金额构成"卡片。
- 已迁移：300394 三季报与一季报、300570、300548、600690。其余 V1 报告需补上年同期源格后迁移。

## 4. 设计 token 与排版

- 颜色：收入源 `#9CABB2`；合计 `#263F47`；成本费用 `#CD7271`；利润 `#239878`；背景 `#F8F7F2`；纸面 `#FFFEFB`；正文 `#19333C`；辅助文字 `#617875`；负值使用铜色/红色并带"−"号。
- 字体：标题 Noto Serif CJK SC / 宋体回退；正文与数字 Noto Sans CJK SC，数字使用等宽数字 `font-variant-numeric: tabular-nums`。
- 字号：图中金额 ≥ 13px（手机 ≥ 12px），节点名称 ≥ 13px，脚注 ≥ 11px；任何金融标签 < 10px 是 FAIL。
- 标题：桌面 2–3 行内；不出现单字孤行（例："用。"独占一行是 FAIL）。
- 单位：亿元保留两位；百分比一位或两位；pp 表示百分点；正负号显式。
- 每张图：桌面 1040/1100 宽、手机 330 宽**两套原生构图**，不缩放、不横滑、不隐藏。

## 5. 图序节奏

- EDITORIAL_V2：第一屏是 KPI 看板与损益流向图；旧版式第一屏只出现一张大图（完整利润主线）。
- 相邻两张图不能回答同一个问题；若利润签名桥（E4）只是主线的重画，让它进入核对区（编辑清单 `role: reference`）。
- 图与文交替：每 2–3 张图插入一段研究文字（`essays`），而不是把所有文字堆在最后。
- 反证与边界紧贴图下，不集中到附录。

## 6. 编辑清单（`research/editorial-20261113/<code>.json`）的角色

- `primary`：完整利润主线（自动）。
- `secondary`：回答新问题，留在正文。
- `reference`：已被主线覆盖或只供核对，折叠到"完整核对"区；`rationale` 写清为什么下沉。
- `summary: true` + `focus`：在正文留一张阅读卡，只展示 focus 中列出的关键行，并链接到完整原图。

选择标准见 `docs/PROFIT_CHAIN_EDITORIAL_STANDARD.md`：重要性同时看金额、占利润比例、同比贡献、方向变化与特殊风险，不用固定 Top3 或图表配额。
