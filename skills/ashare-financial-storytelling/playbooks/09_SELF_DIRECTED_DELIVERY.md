# Playbook 09 · 自驱研究主编与视觉总监：从新PDF到可靠交付

**目标不是让用户反复指出漏项，而是作者在第一次请求评审之前主动发现、修复和复验。** 先读本页，再读 Playbook 08 选题；源数据、图证、研究、审美和发布属于五项不同责任。任何工具自评不得充当独立专家认证。

## 0. 从用户输入到执行者独立决策

用户只提供一份财报 PDF（必要时提供公司代码、报告期、原件 URL）。优先从原件封面、财务附注和公司目录自动识别身份、合并口径、期间与行业；只有**无法从原件与现有渠道消除的重大身份/来源歧义**才询问用户。无需用户逐条指定图、研究点和颜色，不得在可自动复核的细节处反复索要反馈。

将执行状态记为 SOURCE_READY → RESEARCH_PLANNED → FIRST_DRAFT → EVIDENCE_RECONCILED → REAL_BROWSER_REVIEWED → PEER_CALIBRATED → PR_VERIFIED → MAIN_LIVE_VERIFIED。每个状态有证据，不得用「已运行」冒充「已经达标」。

## 1. 第一次写稿前完成“重大问题覆盖矩阵”

先运行：

```bash
T=skills/ashare-financial-storytelling/tools
python "$T/start_report.py" /absolute/path/report.pdf
python "$T/v2_builder.py" capabilities --code <code> [--period <period>]
python "$T/research_evidence.py" --code <code> [--period <period>]
```

先从 `editorial-opportunities.json` 打开公司最可能改写叙事的原始附注页，人工回读原表。来源能力矩阵用于确保基本问题覆盖，同时容纳实际原件暴露的额外重大问题。

拿到原件后主动核对：公司怎么挣钱、营业收入/营业成本与分部经济性、归母与扣非及减值/投资收益、净利润→CFO完整调节、经营现金与现金资本开支、应收存货和营运资本、融资/现金等价物、负债及到期项、风险与下一期反证。银行/保险/券商/地产换用对应合法语义；尚无适配器时明示 NOT_ESTABLISHED 并拒绝，不得生套工业公式。

**三类决定必须记录**：(A) 披露足够且影响结论 → 正文研究 + 合法图种；(B) 有事实但不宜独立成图 → 正文数据与折叠核对表；(C) 披露不足或同口径不成立 → 明确省略原因、来源原页和需补证据。年度稿不能把已提取的产品成本、现金补充资料、债务明细留在账本里，却只给短讯式四图摘要。没有数据不得凑图、制造季度、量价因果或估值。

## 2. 主编先回答问题，再规划图形

按 Playbook 02 的八个问题和 Playbook 08 的双选题，形成结构化 `research-brief.json`。至少找到最能改变研究结论的披露，展示**量化机制—最强替代解释—能区分两者的证据—下一期证伪指标**。把 DISCLOSED、DERIVED、MANAGEMENT、HYPOTHESIS、NOT_CHECKED 分开；管理层解释不等于已被证明的业务驱动。

按 [Playbook 08](08_EDITORIAL_DECISIONS.md) 把竞争选题的取舍与读者论证图写入现有研究简报。技能启动的新原件 dossier 在编译前检查这一决策与源键、论点、图 ID 是否对应。

每张图先写 30 秒简报：**研究问题 / 源键和原页 / 口径、期间、合并范围 / 选此图的原因 / 三秒读出什么 / 少了此图损失的判断 / 最强替代解释**。每张重要图不得只因「已有某个 family」就认定已覆盖：编译器必须看到真实金额键，尤其现金、净利→CFO和期间存量桥。

## 3. 通用图形编译与“不能假画”的审计

图种由经济关系决定：守恒收入/成本→真实 Sankey，利润与现金正负变动→签名桥，期间金额→同比对比，比例→同轴比率，时点存量→存量差额或资产恒等式。每图的来源键必须真实参与渲染，给百分比、实际金额、期末存量**各自正确的几何校验**。不接受仅凭 family、标题中出现 cfo/cash_close、或 SVG 元数据未定义就打 PASS。

强制运行已有精确 Decimal 源值、原件行列、期间/存量流量、图形守恒与编辑几何审计，失败后改数据源/结构，而非抹掉拒绝断言。每一次修复在 `quality-regressions.json` 登记根因、反例、测试路径与推广边界。

## 4. 盲视图审稿：不要只依赖「0 重叠」

打开**实际当前 HTML SHA** 的完整桌面 1440、平板 768、手机 Chromium 390 和 Safari WebKit 375 截图，包括每张图、首屏、整页图文顺序及当前真实 SVG 下载。对每张图遮住解释文本：读者 3–5 秒能否直接认出问题、最大数字和结论？收入、成本、毛利的视觉权重与数值尺度是否一致？同类图是否重复说明同一发现？中文长标签、负数、注释与轴线是否形成明确层级？图与正文的白空间、字体级差、颜色语义、焦点节奏是否与整体设计协调？

选两份不同公司的当前成稿并排读。第一份优先匹配经济机制与期间；第二份优先匹配视觉任务，例如高密度现金桥或狭窄手机屏的首图。行业或期间缺少近例时记下可借鉴和不可类比之处。推荐列表按行业、适配和期间排序；任一满足现时字节的相关作品可用于校准。同公司上期只用于跟踪判断。对比核心问题、拆解广度与深度、信息密度、主图艺术指导、标注精细度、桌面/手机首屏及整篇节奏。输出**具体差距与一项可执行修改**，不能写「整体高级、已达顶级」或只打 R/V 分。图少但证据充分时合理；图多且重复、视觉拥挤仍要删改。学习系统的风格语法，不复制其他作品的图像、品牌或字体。

## 5. 自动生成修订清单，作者自己返工

```bash
python research/shared/autonomous_editorial_audit.py --code <code> \
  --out work/editorial/<code>-issues.json \
  --review-template work/editorial/<code>-author-tasks.json
# 后续同一公司新报告期使用 --code '600036@2026Q1' 这样的身份
```

输出每一个已披露、应解释而尚未解释的**事实支持问题**、来源键、准确图形引用、两份推荐同库报告、每图复核任务和当前缺口。模板字段一律为 NOT_CHECKED，**不得把生成模板当成实际完成视觉检查**。执行者亲自查看真实截图，填写 `editorial-self-review.json` 的 `peer_calibration.peers`（各含现时 HTML SHA、research_delta、visual_delta）和逐图 `chart_reviews`，每图写 five_second_answer、source_and_grammar、visual_hierarchy、mobile_readability、alternative_and_why_this_graph、peer_design_delta、revision_decision。

把实际误读或论证缺口写成「位置、读者得到的错误答案、应改动的稿件或图、复验所见」，优先修上游造成的多处问题。若核心证据有变，重做选题和主图选择。若研究成立但图证无区分力，先尝试另一种合法关系表达。

修订过程按缺陷优先级：P0 数据/会计/来源/错误图形 → P1 漏掉重大机制、审美视觉结构、真实移动阅读 → P2 微交互与润色。每次修订刷新 HTML SHA、图证和自评；旧证据自动失效。自评达到 Playbook 05 的 R1–R5/V1–V6 评分下限是**必要非充分**条件。

## 6. 无需用户督工的退出条件

```bash
# 新增/修改的报告：对相应代码与报告期严格拒绝未完成审稿
python research/shared/autonomous_editorial_audit.py --code <code> --strict
# PR中仅验证被修改的报告（非整库历史人工改造宣称）
python research/shared/autonomous_editorial_audit.py --since origin/main --strict
```

严格模式任何 BLOCK 或 REVISION 都不能视为可晋升。它仍**不会机器评判主编判断的真实性或艺术品味**：执行者需真实盲视图复核，独立财经/美术二审若没有完成就保持 NOT_CHECKED。没有用户参与，能补就自行补、能跑就自行跑；遇原 PDF 不存在、会计矛盾或缺重大附注且无法合法解决时，停止发布并交付清晰的来源限制，不让用户替系统找 BUG。

**合并前**：至少审计当前候选与原版差异、两家对标源图、全部受影响旧公司逐字节重建、负例测试、双浏览器截图。改变共享 SVG 代码不能修改历史短标签图的输出，除非同时对旧报告显式重建并重新审稿；修复不能靠降低质量阈值。**合并后**：Cloudflare 线上首页及报告完整 HTML SHA、真实导航和 SVG 下载必须独立成功。PR 绿灯、线上一致、自评分数各自有证据，不得相互代替。

## 6a. 真实泛化与门禁适用范围：不得把绿灯当认证

1. 主编自主分析必须同时通过 `research_evidence.validate`（原件 SHA、期间、行业、同科目可比与 Decimal 逐元算式）和 `autonomous_editorial_audit`（事实机会、图形、作者复核、同库参照）；研究简报仅存在、结论写得漂亮或会计恒等式闭合都不代表研究通过。
2. 对财报 `source/` 原件、`extracted/` 逐页材料、`visual-qa/` 图证及其他发行人档案的修改，按“报告需要重新审稿”处理；目录新增报告亦然。不得只根据 `publication.json` 是否改动判断需要复验。
3. 若本次提交只改共享审计器或 Skill，而 `--since` 得出 `count=0`，只能称 `NO_REPORT_CHANGED_NOT_AN_EDITORIAL_CERTIFICATION`；仍须运行恶意负例/已知样本测试，不能写“全公司分析及美学已通过”。共用渲染/来源工具变化必须通过其依赖公司回归后才能准入。
4. 研究新稿在 `browser_evidence` 保存 `chromium_receipt` 与 `webkit_receipt`。同一 HTML SHA、四个原生视口、准确有序的图 ID、非空财务数值、无重叠或裁切都通过后，再填写作者判断。CI 只归档采集的结果，作者逐图修改意见和对标结论由实际读图者记录。
5. 工业 FY/H1、金融 Q1、保险 CAS25 等须保留分行业适配与实际盲测范围说明。源数据通过、审稿完成、网页发布、独立专业二审是四种不同证据；后者没有发生就必须是 `NOT_CHECKED`。

## 6b. 加快首轮成稿与复验

1. **先排证据再排图。** 工业公司区分本期产品毛利、同比利润驱动与现金兑现。银行先接通日均余额与资产、负债定价，再把净利息增量逐项桥接到归母利润。两期都须独立核对营业利润、税前、合并净利和归属。若原报披露不良、关注、逾期、拨备或同法监管资本变化，将足以改变判断的数值带进正文；期末贷存规模只有在能区分解释时才作主图。直接引述非金额附注使用 `article.source_quotes` 提供物理页与原文字串，用 `[quote:键名]` 在正文引用，由编稿器核对完整 PDF 指纹和实际原页。
2. **利润图保留披露小计。** 会计利润链先用各披露项目和实际符号逐元计算。图面只显示重要的合并组，完整原始明细给核对层。签名桥可在 `source_checkpoints` 用原始行索引绑定营业利润、利润总额及合并净利润。验证中间小计和最终归母，两次检查各有用途。
3. **一次构建完成四项同步。** 先生成并比较完整 HTML，再以同一版写入编辑清单、当前候选 SHA、四视口图证和目录图数。调试时优先只重建被影响的公司，最终扫描全部实际使用该图语法的目录网页。对旧出版器保留干净重建的字节比较，支持展开核对层的报告在浏览器中先验证默认阅读，再展开目标图。
4. **先读图、后记分。** 手机先看首屏的一句话和关键数字，随后逐图检查金额标签、图下反证和等待展开的数据。对标抓一个具体差距，例如海尔的分部贡献、长芯的现金约束、银行的平均余额分解。先补改变结论的事实，先删除重复速览，再决定是精简图例、缩短量纲标签还是换为可复算的图种。最终保留同一版本的桌面、手机截图及出图 SHA。除文字之间，还要检查点、箭头、标记是否盖住文字，特别是比率接近轴上限时。
5. **定位首个失败步骤。** 按原件和口径、研究与图清单、重建字节、真实浏览器、部署顺序检查。收到同一上游缺陷的多个失败工作流时，先修一次上游，再复验下游。记录用时、返工轮数及需用户介入的原因。连续跨公司盲测时将首稿和返工版本分开保存。

## 7. 将每次纠错变成跨公司能力

| 此次真实问题 | 下一次自动拒绝/主动预防 |
|---|---|
| 250 项账本事实却只生成 4 张摘要图 | 从来源能力自动发现未被真实图源覆盖的重大研究问题，先补研究或说明不能画的原页原因 |
| 只看 family/title 字符串就把图算作覆盖 | 使用真实原始源键与图形数据字段，拒绝文本伪造 |
| 产品收入与毛利错误地引用同一来源 | 每个金额标记绑定自己可复算的收入或收入减成本表达式 |
| 用银行/保险样板遗漏工业自身利润逻辑 | 来源/会计报表格式路由；复核公司实际业务，不因一行金融科目改行业 |
| 期初/期末存量、同比流量、净利→CFO混画 | 强制原件期间与存量流量标记；数值尺度按各图族独立重算 |
| 手机长标签、负数文字碰撞 | 真正两套原生布局、遮正文盲视图，手机Safari375的真实CJK字宽与整篇节奏评估 |
| 修有研意外改变海尔增速图字节 | 回归所有依赖该共享组件的发行人；冻结旧版字节，长标签仅条件分支 |
| CI 全绿但稿件研究深度及审美仍不够 | 以源事实矩阵、同库双样本真实对照、逐图修订记录和独立人工待审边界分开评估 |
| Cloudflare 与另一客户端给出不同HTML | 统一真实 HTTP/浏览器请求契约；记录响应 SHA/缓存状态，绝不放宽原字节一致性 |
| `python -O` 关闭 `assert` 导致假绿 | 新 Skill 和 CI 必须不开 Python 优化模式执行源证明和负例测试 |

此工作流适用于新公司、续期报告和新行业。**未知真实报告的盲测绩效才衡量泛化成功**；已知 600206 改进不能外推为所有行业长期 L3 成熟度。
