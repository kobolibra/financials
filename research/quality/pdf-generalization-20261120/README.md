### 研究和视觉

- 招商银行 p.5–6、17。净利息收入增加 26.46 亿元，利息收入减少 29.62 亿元，利息支出减少 56.08 亿元。以两期平均余额、原始利息收支和上期真实季度比率拆解，资产扩张的正贡献被收益率与结构项抵消，不能独立识别结构与每份合约定价。原件 p.6 已拆贷款与其他业务减值，因此正文保留这个证据。
- 有研新材 p.90、91、94、194。毛利增加 3.21 亿元，存货与经营性应收合计吸收 6.71 亿元，经营现金为 -0.79 亿元。备货与结算时点是有竞争力的暂时性解释，需在下一次披露看订单覆盖、库龄和回款。现金流调节附注决定用现金桥起笔。
- 作者复核桌面、平板、手机三套图，每稿三张。首图五秒作者读图分别记录为「少付利息覆盖少收利息」与「存货、应收使正利润变成负经营现金」。边界分别是「会计分解无法单独识别定价原因」和「调节额不能说明占用持续多久」，均需要带图注阅读。独立 AI、真人读图和独立财经审阅均为 NOT_CHECKED，作者自查两类归因错误各 0，独立错误计数未测。两稿每张图各自回答驱动、结果与资金约束三类问题。没有删除遗留报告。
- Chromium 145，1440/768/390，断网打开、真实 SVG 下载、原始金额比例、负值零轴、图中文字边界和横溢出均检查。当前主机 WebKit 缺系统依赖，PR 工作流有独立环境。首次本地 Chromium 失败因运行时禁止 Unix socket，实际图证改用 Chrome Headless Shell。物理设备 NOT_CHECKED。

### 效率

历史太辰光已有手工规格的发布重建 2.43 秒，字节一致；从陌生 PDF 首次研究耗时没有可比历史基线。旧招商银行案例是专用作者脚本，使用恢复的原件重建 9 图。新报告的机器阶段计时见 [重建回执](rebuild-receipt.json)。Chromium 两份稿约 3.6 秒/份，运行并发。招商银行手工编排四个平均余额格、研究解释与图序。有研新材复核十个比较数字、现金附注及行业/产品界线，调整研究首图，复用自动提取的现金调节。初次运行和返工原因可查；编辑与研究阶段未做连续独立计时。程序自动重读原件的报表抽取和源格，避免错列重复人工核对，代价是预检和发布各重读一次。

Linux 浏览器需要 Chromium 或 `--executable` 指定 Chrome Headless Shell，以及 Noto CJK 字体。WebKit 依赖齐备时加 `--engine webkit`。成稿默认在 `work/candidates/`，逐图数据和源格在对应 dossier，HTML 本身嵌入源账本。基于 JSON 作者规格的回放和新会话的研究质量是不同证据。

只给陌生 PDF 的命令为 `python skills/ashare-financial-storytelling/tools/start_report.py /absolute/filing.pdf`。自动取证并进入作者环节的路径已用两份指定 PDF 从空目录复验。主稿成稿步骤见 [新会话入口](../../../START_HERE.md)。故意用招商银行本期源格及金额替换 `nii_prior`，原件重放以 `OFFLINE_CANONICAL_SOURCE_COLUMN_DRIFT nii_prior` 拒绝。

## 剩余缺口

1. 完整的独立新发行人端到端复验。在重庆银行已存技术草案基础上，由未参与实现的作者只读 PDF 完成研究和视觉，再从不同发行人复验薄披露场景。
2. 继续验证语义。对新披露的监管、分部重述和跨季累计差分建立成对原件及同口径证明。含金融子公司的工业集团和保险、券商、地产仍需各自路径。
3. 独立财经与视觉复核，加真人五秒读图。WebKit 以 PR 实际运行回执为准。机器技术门禁无法代替阅读实验。
4. 历史未映射行仍需分场景逐页复核。先看会改变主线的行，记录消费指标和阻断范围。重跑并记录提取修订前后的差异。
5. 对下一份全新输入单独计时研究、映射复查、编辑及返工，建立可比较的人工成本基线。
